# az1k — портфолио

Клиентский сайт-портфолио: Nuxt 4, TresJS (three.js), Tailwind CSS 4, i18n RU/EN.

```bash
pnpm install
pnpm dev        # http://localhost:3000
pnpm build      # прод-сборка + пререндер всех страниц
pnpm typecheck
```

## Что нужно доделать перед публикацией

Это места, где стоят заглушки или мои догадки. Проверь их — остальное готово.

| Что | Где поменять |
|---|---|
| **Цены — выдуманные.** Поставь свои. | Админка → «Цены, контакты и стек» |
| У трёх проектов стоит галочка «требует проверки»: стек и описание собраны по внешнему виду сайта. | Админка → «Проекты» |
| **Файла резюме нет** — кнопка «Скачать резюме» ведёт в 404. | Положи PDF в `public/` |
| Домен задан как `https://portfolio.vercel.app`. | `nuxt.config.ts` → `SITE_URL`, `public/robots.txt`, `public/admin/config.yml` |
| Настройки OAuth для входа в админку. | См. раздел «Админка» ниже |

### Проекты, требующие проверки

`azt-store`, `kicks`, `alfa-marketing` помечены галочкой «требует проверки».
Для `kicks` и `alfa-marketing` сайты не открывались из окружения сборки,
поэтому стек указан предположительно. Уточни списки технологий и, если
помнишь, реальные детали задачи — конкретика в кейсе продаёт сильно лучше
общих слов. Галочка служебная, на сайте её не видно.

### Скриншоты проектов

Обложки загружаются через админку и показываются в списке работ и на странице
кейса. Пока их нет, раздел «Работы» остаётся типографским указателем — так
он выглядит законченным, а не сеткой пустых мест под ненайденные картинки.

## Админка на /admin

Проекты, цены и контакты редактируются через веб-интерфейс на `/admin`, без
правки кода. Вход по аккаунту GitHub, сохранение уходит коммитом в этот же
репозиторий, Vercel пересобирает сайт сам — обычно за минуту. Сайт при этом
остаётся статикой: базы данных нет.

Что можно менять:

- **Проекты** — добавлять, удалять, менять порядок, загружать обложки,
  править текст кейса на обоих языках;
- **Цены, контакты и стек** — цены «от», почта, телефон, соцсети, список
  технологий и переключатель «свободен для новых проектов».

Тексты интерфейса (заголовки секций, описания услуг, блок «Процесс») в
админку не вынесены — они меняются редко и живут в `i18n/locales/`.

### Что нужно настроить один раз

**1. Создать OAuth-приложение GitHub** — Settings → Developer settings →
OAuth Apps → New OAuth App:

| Поле | Значение |
|---|---|
| Homepage URL | `https://portfolio.vercel.app` |
| Authorization callback URL | `https://portfolio.vercel.app/api/callback` |

**2. Добавить переменные окружения в Vercel** (Settings → Environment Variables):

| Переменная | Значение |
|---|---|
| `NUXT_GITHUB_CLIENT_ID` | Client ID из OAuth-приложения |
| `NUXT_GITHUB_CLIENT_SECRET` | Client Secret оттуда же |
| `NUXT_ADMIN_GITHUB_LOGINS` | Необязательно. Логины через запятую, кому разрешён вход. По умолчанию `az1ktokhirov` |
| `NUXT_PUBLIC_SITE_URL` | Необязательно. Нужна, если домен отличается от `https://portfolio.vercel.app` |

Секреты нигде в репозитории не хранятся: обмен кода на токен идёт на сервере
(`server/api/callback.get.ts`), браузер `client_secret` не видит.

**3. Проверить ветку в `public/admin/config.yml`.** Поле `backend.branch`
должно совпадать с веткой, которую деплоит Vercel. Сейчас там
`claude/portfolio-rry0s6`. Переименуешь ветку в `main` — поменяй и здесь,
иначе админка откроется, но сохранение будет падать.

### Почему вход устроен именно так

OAuth-приложение просит права на репозитории, поэтому после обмена кода на
токен сервер проверяет логин вошедшего по списку `NUXT_ADMIN_GITHUB_LOGINS`.
Без этой проверки любой человек мог бы через твоё приложение выписывать себе
токены. Дополнительно каждый запрос защищён одноразовым ключом в куке —
чужой запрос с подставленным кодом авторизации отбивается.

## Как всё устроено

```
content/          ← сюда пишет админка
  projects/       по файлу на кейс, имя файла = адрес страницы
  settings.json   цены, контакты, стек, статус занятости
app/
  data/           загрузчики контента: projects.ts и site.ts
  components/
    hero/         3D-сцена: HeroVisual → HeroScene → HeroBlob + shaders.ts
    sections/     шесть секций главной
    base/         переиспользуемые куски
  pages/          index.vue и work/[slug].vue
  plugins/        reveal.ts — появление блоков на скролле
  utils/          capabilities.ts — что тянет устройство
i18n/locales/     ru.json, en.json — тексты интерфейса
public/admin/     страница админки и её схема полей
server/
  api/            auth и callback — вход в админку через GitHub
  routes/         sitemap.xml.ts
scripts/          copy-cms.mjs — кладёт бандл админки в public при сборке
```

### Почему контент лежит в файлах, а не в базе

Компоненты подхватывают `content/projects/*.json` через `import.meta.glob`:
Vite разворачивает это на этапе сборки и встраивает данные прямо в бандл. На
рантайме обращений к диску нет, поэтому все страницы по-прежнему
пререндерятся в статику — админка появилась, а скорость не изменилась.

Одна тонкость: `import.meta.glob` — возможность Vite, а папка `server/`
собирается rollup-ом и такого синтаксиса не понимает. Поэтому список слагов
собирается в `nuxt.config.ts` чтением папки и раздаётся дальше — в
`prerender.routes` и в `runtimeConfig` для карты сайта.

### 3D-сцена

Фигура — икосаэдр, вершины которого смещает фрактальный симплекс-шум в
вершинном шейдере; нормали пересчитываются там же, иначе объём пропадает.
Цвет даёт френель: тёмная середина, светящийся край.

Сцена бережёт загрузку:

- канвас поднимается только после `requestIdleCallback`, отдельным чанком
  (~216 КБ gzip), который браузер тянет низким приоритетом через `prefetch`;
- на мобильных меньше полигонов (detail 4 против 6) и ниже DPR;
- при `prefers-reduced-motion` и без поддержки WebGL показывается статичный
  CSS-градиент — он же виден при SSR, поэтому первый экран никогда не пустой.

### Появление блоков на скролле

`v-reveal` (`app/plugins/reveal.ts`) прячет элемент **только из JavaScript** и
показывает через IntersectionObserver. Если скрипт не выполнился, атрибут не
появится и контент останется видимым. Обратная схема — прятать в CSS и
показывать скриптом — оставила бы часть посетителей с пустой страницей.

### Языки

Русский на корне (`/`), английский на `/en`. Тексты интерфейса — в
`i18n/locales/`, тексты кейсов — рядом с проектом в `projects.ts`, потому что
кейс удобнее править целиком в одном месте.

## Деплой

Статика: `pnpm build` кладёт готовый сайт в `.output/public`, все 12 страниц
(5 кейсов × 2 языка + 2 главные) пререндерятся. На Vercel проект собирается
без дополнительной настройки — Nuxt определяется автоматически.
